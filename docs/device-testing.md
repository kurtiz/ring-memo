# Galaxy A21s capture experiment

Target: Samsung Galaxy A21s, Android 12. Exact variant, firmware, and ABI are collected in the app's exported report. No physical-device result has been recorded yet.

## Build and install

Use Node 22+, pnpm, Java 21, and an Android SDK with platform 36, build tools, NDK, and CMake. The project uses Expo SDK 57. Java 25 from the current Android Studio installation failed in this project's native C++ tooling; use Java 21 instead. Native source lives in `apps/mobile/modules/ringmemo-recorder`; manifest configuration lives in its manifest and `apps/mobile/plugins/with-recorder.js`. Never edit the generated app Android directory by hand.

```powershell
pnpm install
$env:EXPO_NO_TELEMETRY = '1'
pnpm --filter @ringmemo/mobile exec expo prebuild --platform android --no-install
# Set JAVA_HOME and ANDROID_HOME to your local installations.
Push-Location apps/mobile/android
./gradlew.bat :app:assembleRelease :ringmemo-recorder:testReleaseUnitTest --no-daemon --max-workers=2 -PreactNativeArchitectures=arm64-v8a
Pop-Location
```

The release APK is `apps/mobile/android/app/build/outputs/apk/release/app-release.apk`. It embeds the JavaScript bundle and does not require Metro. This prototype uses the generated project's local debug signing key, so it is for direct device installation, not publishing. Keep that key if you need to update an existing installation without losing its library.

On Windows, `powershell -ExecutionPolicy Bypass -File scripts/build-apk.ps1` runs the checks, generates Android, builds the APK, runs native tests, and copies the result to `artifacts/ringmemo-a21s.apk`. It uses an explicit `JAVA_HOME`, otherwise prefers a Java 21 runtime unpacked in `.tools/jdk21`, and detects the standard Android SDK path. Gradle caches stay inside the workspace. Use `-SkipChecks` only when the checks have already passed for the same code.

The workspace uses a root `.pnpm` virtual store with shorter package directory names to keep generated C++ source paths below Windows' path limit. Run `pnpm install` after changing these settings. The `with-native-build-paths` config plugin also places native staging files in the workspace root's ignored `.cxx` directory. The build script downloads checksum-verified Ninja 1.13.2 into `.tools/ninja`; the plugin uses that executable or an explicit `RINGMEMO_NINJA` path. For direct Gradle builds on Windows, provide Ninja 1.12 or newer as described in the [Reanimated Windows guide](https://docs.swmansion.com/react-native-reanimated/docs/guides/building-on-windows/). The Gradle settings are regenerated by Expo prebuild.

Enable USB debugging, connect the A21s, and install with `adb install -r <apk-path>`. Alternatively copy the APK to the phone and install it through Android's file manager. Do not uninstall an existing RingMemo installation unless you have exported the recordings you want to keep.

## Start the helper

1. Install Shizuku from its [official download page](https://shizuku.rikka.app/download/).
2. Follow its [setup guide](https://shizuku.rikka.app/guide/setup/) for wireless debugging on Android 12, or start it through ADB.
3. Open RingMemo → recording setup. Acknowledge consent and grant audio and phone-state permissions.
4. Authorize RingMemo in Shizuku and wait for the app to show a connected helper.
5. Allow recording notifications. Keep the service notification visible whenever a test or automation is armed.

Shizuku's ADB process runs as UID 2000. It is not a system app and may lack access to VOICE_CALL. Authorization alone does not prove capture works. The experiment does not record Accessibility audio, switch the call to speakerphone, or fall back to microphone capture.

## Test each call

Use a consenting second participant and ordinary cellular calls. Start with one SIM; dual-SIM and call waiting are outside the prototype's verified support until separately tested.

1. Tap **Arm one test call** while RingMemo is visible.
2. Make or answer a call. Use the handset earpiece. Speak in turns for at least ten seconds, including a distinct phrase from each participant.
3. End the call, return to the library, and play the entire test capture.
4. If the audio is completed, non-silent, and at least three seconds long, save its review: call direction, audio route, whether each voice is intelligible, and whether the app was in the background / the screen was locked during capture.
5. Repeat five incoming and five outgoing handset calls. Include at least one background test and one locked-screen test.

The automatic switch unlocks only after those reviewed handset results pass for the current firmware, helper UID, and capture implementation. Reviews are manual evidence, not automatic audio-quality detection. Deleting a reviewed test removes it from the evidence set. Speakerphone and Bluetooth reviews are recorded but do not count toward the handset gate.

When changing the native capture implementation, bump both the capture version in `RecorderStore.identity` and the Shizuku UserService version so old evidence is invalidated and the helper reloads its code.

| Scenario | Expected result | Actual result |
| --- | --- | --- |
| Five incoming handset calls | Both voices intelligible; start and stop without UI involvement | Not tested |
| Five outgoing handset calls | Both voices intelligible; dialing audio may precede conversation | Not tested |
| Background call | Native capture continues; notification remains visible | Not tested |
| Locked-screen call | Capture continues through lock and unlock | Not tested |
| Speakerphone / Bluetooth | Record route-specific result without claiming support | Not tested |
| Missed / rejected incoming call | No recording created | Not tested |
| Cancelled / unanswered outgoing call | Dialing may produce a capture; do not count it as a both-voice result | Not tested |
| Consecutive calls | Separate recordings; no duplicate capture for repeated OFFHOOK | Not tested |
| Stop in notification | Stop current capture; do not restart it during the same call | Not tested |
| Shizuku termination | Disarm and mark interrupted/failed; no successful result claimed | Not tested |
| Permission / notification revocation | Stop or disarm; require setup again | Not tested |
| Low storage / write failure | Failed or interrupted entry with an error | Not tested |
| Reboot / process interruption | Do not start capture silently; reopen and rearm explicitly | Not tested |
| Rename / notes / search | Preserve edits after reconciliation and restart | Not tested |
| Export / delete | Play exported WAV; delete private audio and library entry | Not tested |

## Failure report and root research

Export the device test report after each failure and after completing the matrix. The report includes firmware, helper identity, capture source, capture errors, PCM byte count/peak, and saved reviews. It excludes audio, titles, notes, and file locations. Review the device details before sharing it.

If ADB capture is denied, document the exact error first. Next research whether the exact A21s variant can host a root-started Shizuku process. On an already provisioned root test device, start Shizuku with root and repeat the same experiment; the app recognizes UID 0 and requires fresh reviews. Root identity can still fail Android audio permission or SELinux checks, and this implementation makes no guarantee that root enables VOICE_CALL.

Do not unlock, flash, disable SELinux, or alter Samsung firmware as part of the diagnostic APK setup. Those are separate device changes requiring a concrete device-specific procedure and explicit approval. If both helper modes fail, keep automation disabled and attach the evidence to the feasibility report. A future privileged system integration would need its own design.

## Verification commands

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm check:expo
```

Native unit tests cover call deduplication, missed calls, stop suppression, the verification threshold, and WAV headers. JavaScript tests cover permission/helper/consent gates, review eligibility, SQLite reconciliation, literal search, and retrying incomplete deletions. These checks do not replace the physical-device matrix.
